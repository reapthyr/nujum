=== VERCEL ENVIRONMENT VARIABLES ===
Set these in Vercel: Project -> Settings -> Environment Variables -> Production
(Use `vercel deploy --prod` if the variables are Production-only.)

DATABASE_URL    = postgresql://postgres.<PROJECT_REF>:<PASSWORD_URL_ENCODED>@aws-1-<REGION>.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
DIRECT_URL      = postgresql://postgres:<PASSWORD_URL_ENCODED>@db.<PROJECT_REF>.supabase.co:5432/postgres?sslmode=require
AUTH_SECRET     = base64 string (openssl rand -base64 48)
AUTH_DISCORD_ID = Discord application ID
AUTH_DISCORD_SECRET = Discord OAuth client secret
NEXT_PUBLIC_APP_URL = https://<your-vercel-domain>   # no trailing slash
BOT_API_URL     = http://<VPS_PUBLIC_IP>:8080
BOT_API_HMAC_SECRET = 64 hex chars (openssl rand -hex 32) -- MUST match bot/shared .env
DASHBOARD_OWNER_IDS = comma-separated Discord user IDs
SESSION_MAX_AGE_SECONDS = 28800
SESSION_UPDATE_AGE_SECONDS = 900
REAUTH_WINDOW_MINUTES = 15
DASHBOARD_RATE_LIMIT = 120

IMPORTANT: if the database password contains special characters, URL-encode them.
Example: password `abc@def` must be written as `abc%40def` inside the URL.

=== VPS (direct Node.js, no Docker) ===
1. Clone: sudo git clone https://github.com/reapthyr/nujum.git /opt/nujum
2. Env files: apps/bot/.env and packages/shared/.env (chmod 600)
3. Build (raise heap on small instances):
   cd /opt/nujum
   export NODE_OPTIONS="--max-old-space-size=1024"
   pnpm install --frozen-lockfile
   pnpm --filter @nujum/shared build
   pnpm --filter @nujum/bot build
4. systemd service runs: node /opt/nujum/apps/bot/dist/index.js
   sudo systemctl enable --now nujum-bot
5. Open TCP 8080 in BOTH Oracle Cloud security list and the OS firewall.
6. Healthcheck: curl http://<VPS_PUBLIC_IP>:8080/healthz

=== DATABASE MIGRATIONS ===
Run from a machine that can reach the database (the VPS works well):
   cd /opt/nujum
   DIRECT_URL='<pooled-url>' pnpm --filter @nujum/shared db:deploy
